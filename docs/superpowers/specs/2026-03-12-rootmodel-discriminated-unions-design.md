# RootModel Discriminated Unions Design

**Date:** 2026-03-12
**Status:** Approved
**Supersedes:** `2026-03-12-tagged-discriminated-unions-design.md`

## Problem

The previous tagged discriminated unions implementation achieved correct `tag` discriminant fields on individual schemas, but the generated TypeScript types have two issues:

1. **No named union types** — `ProductResult` is a Python type alias (`Annotated[Union[...], Field(discriminator="tag")]`), not a Pydantic model class. Django Ninja can't create a named `$ref` component for it, so it gets inlined in every response.
2. **Redundant intersection noise** — hey-api adds `{ tag: 'available' } & AvailableProductSchema` intersections whenever it sees `oneOf + discriminator` in OpenAPI. There is no config to suppress this.

Additionally, the product schemas duplicate model field definitions instead of deriving them from the Django model.

## Goal

- `ProductResult` appears as a **named TypeScript type**: `AvailableProductSchema | OutOfStockProductSchema`
- Error unions are already generated by hey-api (e.g., `ProductsApiGetProductError = ProductNotFoundError | ProductHiddenError`) — no changes needed
- Product schemas derive fields from the Django model via `ModelSchema`, not manual duplication
- Auth errors are handled globally via client interceptor, not per-endpoint typed unions

## Constraints

- Django model `status` field is not renamed — only the Pydantic schema layer changes
- HTTP status codes are preserved (200/403/404)
- hey-api configuration (`openapi-ts.config.ts`) is unchanged
- `tag` is the discriminant field name (unchanged from previous design)

## Design

### Core Infrastructure (`core/schemas.py`)

Two base classes for two use cases:

**`TaggedSchema`** — for schemas not backed by a model (errors, manually constructed responses). Unchanged from previous implementation.

```python
from ninja import Schema
from pydantic import ConfigDict

class TaggedSchema(Schema):
    model_config = ConfigDict(populate_by_name=True)
    tag: str
```

**`TaggedModelSchema`** — NEW. For schemas backed by a Django model. Auto-derives fields via `Meta` class.

```python
from ninja import ModelSchema
from pydantic import ConfigDict

class TaggedModelSchema(ModelSchema):
    model_config = ConfigDict(populate_by_name=True)
    tag: str
```

**`AppError`** — unchanged. Inherits `TaggedSchema` (errors are not model-backed).

```python
class AppError(TaggedSchema):
    detail: str
```

**`tagged_union()` is removed.** Replaced by explicit `RootModel` subclasses per resource.

### Product Schemas (`products/schemas.py`)

Success schemas use `TaggedModelSchema` with `exclude` to derive fields from the model:

```python
from typing import Literal
from pydantic import Field, RootModel
from core.schemas import AppError, TaggedModelSchema
from products.models import Product

class AvailableProductSchema(TaggedModelSchema):
    tag: Literal["available"] = Field(validation_alias="status")

    class Meta:
        model = Product
        exclude = ["status"]

class OutOfStockProductSchema(TaggedModelSchema):
    tag: Literal["out_of_stock"] = Field(validation_alias="status")

    class Meta:
        model = Product
        exclude = ["status", "stock_count"]
```

**`RootModel` for named union** — this is the key change. Instead of a type alias, `ProductResult` is a proper Pydantic model class. Django Ninja registers it as a named `$ref` component in OpenAPI.

```python
class ProductResult(RootModel[AvailableProductSchema | OutOfStockProductSchema]):
    pass
```

The OpenAPI output uses `anyOf` without a `discriminator` key. This causes hey-api to generate a clean union (`AvailableProductSchema | OutOfStockProductSchema`) instead of the noisy intersection pattern.

TypeScript narrowing still works because each individual schema has `tag` as a unique literal type.

**Error schemas** — unchanged, inherit `AppError` (which inherits `TaggedSchema`):

```python
class ProductNotFoundError(AppError):
    tag: Literal["product_not_found"] = "product_not_found"
    id: int

class ProductHiddenError(AppError):
    tag: Literal["product_hidden"] = "product_hidden"
    id: int
```

### Products API (`products/api.py`)

```python
@router.get("/", response=list[ProductResult])
def list_products(request):
    return list(Product.objects.exclude(status=Product.Status.HIDDEN))

@router.get(
    "/{product_id}/",
    response={200: ProductResult, 404: ProductNotFoundError, 403: ProductHiddenError},
)
def get_product(request, product_id: int):
    try:
        product = Product.objects.get(id=product_id)
    except Product.DoesNotExist:
        return 404, {"tag": "product_not_found", "detail": f"Product {product_id} not found", "id": product_id}

    if product.status == "hidden":
        return 403, {"tag": "product_hidden", "detail": f"Product {product_id} is not available", "id": product_id}

    return 200, product
```

Pydantic picks `AvailableProductSchema` or `OutOfStockProductSchema` automatically based on `product.status`.

### Generated TypeScript (via hey-api)

```typescript
// Individual schemas — tag is a literal type
type AvailableProductSchema  = { tag: 'available'; id: number; stock_count: number; ... }
type OutOfStockProductSchema = { tag: 'out_of_stock'; id: number; ... }

// Named union from RootModel — clean, no intersections
type ProductResult = AvailableProductSchema | OutOfStockProductSchema;

// Error union — already generated by hey-api from HTTP status code grouping
type ProductsApiGetProductError = ProductNotFoundError | ProductHiddenError;

// Response uses the named type
type ProductsApiGetProductResponse = ProductResult;
```

### Frontend Usage (ts-pattern)

```typescript
// Success — TypeScript narrows on tag
match(response)
  .with({ tag: "available" }, (p) => p.stock_count)
  .with({ tag: "out_of_stock" }, (p) => p.name)
  .exhaustive()

// Errors
match(error)
  .with({ tag: "product_not_found" }, (e) => e.detail)
  .with({ tag: "product_hidden" }, (e) => e.detail)
  .exhaustive()
```

### Auth Errors

Handled globally via `@hey-api/client-fetch` interceptor. Not modeled as `TaggedSchema`. Django Ninja's `JWTAuth` returns 401 automatically.

```typescript
client.interceptors.response.use((response) => {
  if (response.status === 401) {
    window.location.href = '/login';
  }
  return response;
});
```

## Empirical Verification Needed

Confirm that Django Ninja creates a `$ref` to `ProductResult` (named component) rather than inlining the `RootModel`. If it inlines, we may need to register the schema explicitly. This is an implementation detail — the design is the same either way.

## Scalability Pattern

Every future API follows the same recipe:

1. Success schemas inherit `TaggedModelSchema`, use `exclude` to control fields
2. Error schemas inherit `AppError` (→ `TaggedSchema`)
3. One `RootModel` subclass per resource for the success union (e.g., `PostResult`)
4. Endpoint response uses the `RootModel` type
5. Auth errors handled globally, not per-endpoint

## Changes from Previous Design

| Aspect | Previous | Now |
|---|---|---|
| Union type | `tagged_union()` type alias | `RootModel` subclass |
| Named in OpenAPI | No (inlined) | Yes (`$ref` component) |
| hey-api output | Intersection noise | Clean union |
| Schema field source | Manual duplication | `ModelSchema` + `Meta.exclude` |
| Base class for models | `TaggedSchema` | `TaggedModelSchema` (new) |
| `tagged_union()` helper | Used | Removed |
